# Roadmap: таск-трекер на Go с чистой архитектурой

Продукт: REST API. Проекты (CRUD), задачи внутри проектов, пользователи, админ добавляет пользователей в проект через инвайты. БД — SQLite.

Каждый этап — несколько маленьких задач в `docs/tasks/`. Подробная задача пишется только когда предыдущая принята.

## Целевая раскладка слоёв

```
cmd/api/            точка входа, сборка зависимостей (composition root)
internal/domain/    сущности и бизнес-правила, без внешних зависимостей
internal/usecase/   сценарии приложения; здесь объявляются интерфейсы хранилищ
internal/adapter/   реализации: http (хендлеры), sqlite (репозитории)
migrations/         SQL-миграции
```

Правило зависимостей: стрелки смотрят только внутрь. `domain` не знает ни о ком, `usecase` знает о `domain`, адаптеры знают об обоих, `cmd` знает обо всех.
К этой раскладке придём постепенно — не создавай папки заранее.

## Этапы

| № | Этап | Что делаем | Что осваиваем в Go |
|---|------|------------|--------------------|
| 0 | Скелет | модуль, `main`, HTTP-сервер, `/healthz` | модули, пакеты, `net/http`, `http.Handler`, обработка ошибок |
| 1 | Домен: проект | сущность, конструктор с инвариантами, доменные ошибки | структуры, методы, указатели и значения, `errors.Is/As`, table-driven тесты |
| 2 | Usecase: проекты | сценарии CRUD, интерфейс хранилища, in-memory реализация | интерфейсы на стороне потребителя, внедрение зависимостей, `context`, моки руками |
| 3 | HTTP-слой | `chi`, хендлеры, DTO, маппинг ошибок в статусы | JSON, struct tags, `httptest`, middleware |
| 4 | SQLite | миграции `goose`, репозиторий на `database/sql` | `sql.DB`, сканирование строк, `sql.ErrNoRows`, cgo, интеграционные тесты |
| 5 | Обвязка | конфиг из env, `slog`, graceful shutdown | сигналы, горутины, каналы, `context` с отменой |
| 6 | Задачи | вторая сущность, статусы и переходы, пагинация | типизированные константы, связи между агрегатами, дженерики (умеренно) |
| 7 | Пользователи и вход | регистрация, логин, JWT, auth-middleware | `bcrypt`, значения в `context`, безопасность |
| 8 | Инвайты и участие | роли, токен инвайта, принятие, проверка прав в usecase | транзакции через границу слоёв, гонки, `-race` |
| 9 | Качество | `golangci-lint`, Makefile, Docker, CI, OpenAPI | инструменты, профилирование, возможно `sqlc` |

## Процесс

1. Читаешь файл задачи, задаёшь вопросы, если что-то неясно.
2. Пишешь код сам. Застрял дольше чем на 20–30 минут — проси подсказку, а не решение.
3. Коммитишь, пишешь «ревью».
4. Правишь замечания, пока задача не принята.
5. Отвечаешь на вопросы для самопроверки — своими словами.
