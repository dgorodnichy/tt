# Конспект к задаче 10. Своё хранилище в тестах

Пополняется по ходу задачи: сюда записывается всё, что ты спросил и что мы выяснили.

## Фейк подходит под интерфейс, только если метод совпадает целиком

Имени мало: параметры и результаты должны быть такими же, как в интерфейсе. Метод `Put()` без параметра не подходит под `Put(p *Parcel)`. Компилятор скажет об этом в строке, где фейк передают в конструктор: `wrong type for method Put`. Если параметр внутри не нужен, его всё равно объявляют.

```go
type ParcelKeeper interface {
	Put(p *Parcel)
}

func (k *countingKeeper) Put()          // не подходит
func (k *countingKeeper) Put(p *Parcel) // подходит
```

## Без звёздочки у получателя изменения теряются

`func (k countingKeeper) Put(...)` получает копию структуры. `k.puts++` увеличит копию, а у фейка в тесте останется `0`. Ошибки компиляции нет, тест просто покажет неверное число. Если метод меняет поле — получатель со звёздочкой.

В Ruby `self` внутри метода — всегда тот же объект; в Go без звёздочки — копия.

## Глаголы форматирования (`%v`, `%d`…)

`%n` в Go нет — `go vet` пишет `unknown verb n`. Для числа — `%d`. Поправка к старому: `%q` — это не «ошибка», а строка в кавычках; ошибку печатают через `%v`.

| Глагол | Что печатает |
|---|---|
| `%v` | любое значение, в том числе ошибку — как `to_s` |
| `%s` | строку как есть |
| `%q` | строку в кавычках — как `inspect`, видна пустая строка |
| `%d` | целое число |
| `%t` | `bool` |
| `%T` | тип значения |
| `%%` | знак процента |

Не знаешь, что выбрать, — `%v`. Полный список: `go doc fmt`, раздел «Printing».

## Почему `map` в фейке сохранилась, а счётчик — нет

Встретилось в `create_project_test.go:17`: получатель без звёздочки, тест пишет `called times: 0, want 1`, хотя `Get` проект находит. Копируется сама структура: число в копии — отдельное, а поле с `map` в копии указывает на ту же `map`, что и в оригинале. Поэтому запись в `map` видна снаружи, а `+1` — нет. Лечится звёздочкой у получателя.

## Редактор подчёркивает присваивание полю в методе без звёздочки

`fake_map.go:26`: `fr.GetCalledTimes = ...` в методе `func (fr FakeRepo) Get`. Редактор (staticcheck в `gopls`) предупреждает: присваивание копии ни на что не влияет. Строка `:18` такая же, но там получатель `*FakeRepo` — предупреждения нет. Если метод меняет поле — звёздочка; лучше ставить её всем методам типа одинаково.

## Фейк — глупый и рядом с тестом (ревью 1)

Фейк живёт в `_test.go` пакета, который его использует: в программу он не попадает, а боевой пакет ничего не знает о тестах. Чем фейк проще, тем лучше: один тип — одно поведение, и это поведение видно прямо в тесте (поле, которое тест заполняет сам). «Волшебный» аргумент, включающий ошибку, прячет причину в другой файл: тест `Call("network-error")` не объясняет сам себя.

В Rails то же правило: `instance_double` объявляют в спеке, а не в `app/`.

## Тип из одного `_test.go` виден во всех тестах пакета

Все файлы пакета — одно пространство имён, и тестовые тоже. Фейки для нескольких тестов можно положить в один файл, например `fakes_test.go`; окончание `_test.go` не пускает его в программу. Старые тесты при этом можно оставить на настоящем хранилище: фейк нужен только там, где спрашивают то, чего настоящее не умеет (сколько раз вызвали, «база недоступна»).

## Метод внутри функции объявить нельзя

Тип внутри функции объявить можно, а метод — только на верхнем уровне файла. Значит, тип, объявленный внутри теста, не получит методов и под интерфейс не подойдёт. Фейк с методами — наверху файла (`fakes_test.go`), в тесте только `keeper := &countingKeeper{}`. Пустые `{}` — все поля и так нулевые.

## Где написано, что фейк подходит под интерфейс (В3)

Нигде. У фейка нет слов «реализую `Adder`». Компилятор сам сверяет методы в момент, когда фейк передают в `NewCreateProject`: есть `Add(*domain.Project)` — подходит. Поэтому файл сценария не изменился ни на символ, а тип для него появился новый.
