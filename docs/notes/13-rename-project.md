# Конспект к задаче 13. Сценарий «переименовать проект»

Пополняется по ходу задачи: сюда записывается всё, что ты спросил и что мы выяснили.

## Зачем `Add`, если без него всё работает

Сделал переименование без `Add` — тесты на `memory` зелёные. Причина: в `map` лежит адрес проекта (`*domain.Project`), `Get` отдаёт тот же адрес, `SetName` меняет проект на месте — тот самый, что в `map`.

Но сценарий не знает, что ему дали `memory`. База (SQLite) отдаёт не адрес своей записи, а новый объект, собранный из строки, — копию. `SetName` поменяет копию, в базе останется старое. Поэтому сценарий сохраняет явно: найти → изменить → сохранить.

```ruby
project = Project.find(1)
project.name = "New"
# без project.save в базе всё по-старому
```

Тест на `memory` пропуск сохранения не заметит. Ловит его только фейк-счётчик: «всё верно → сохранение вызвано 1 раз».

## Фейк под каждый тест писать не нужно

Спросил: «получается, под каждый тест своё фейковое хранилище со всеми методами?» Нет:

1. Фейку нужны только методы интерфейса, под который его подставляют, а не всего хранилища.
2. Поведение задаётся полями, которые заполняет тест, а не зашивается в метод. Тогда один тип годится для многих тестов.

```go
type fakeShelf struct {
	book *Book
	err  error
	puts int
}

func (f *fakeShelf) Get(code string) (*Book, error) { return f.book, f.err }
func (f *fakeShelf) Put(b *Book)                    { f.puts++ }

shelf := &fakeShelf{book: someBook}      // успех
shelf := &fakeShelf{err: errStorageDown} // отказ
```

Как `allow(shelf).to receive(:get).and_return(book)` в RSpec: поведение — в тесте, а не в классе.

## Как положить проект в фейк — сначала проект, потом фейк

Путался: «чтобы добавить проект, нужен репозиторий, а чтобы создать фейк, нужен проект». Проект создаётся доменом (`domain.NewProject`), хранилище для этого не нужно. Порядок: сущность → фейк с этой сущностью в поле → сценарий.

```go
book, err := NewBook("b-1", "Go")
if err != nil {
	t.Fatal(err)
}
shelf := &fakeShelf{book: book}
lend := NewLendBook(shelf)
```

Фейк — не хранилище, в него не «добавляют». Ему говорят, что отвечать; его `Add` только считает вызовы. RSpec: `book = build(:book)`, потом `allow(shelf).to receive(:get).and_return(book)`.

## Фейк не должен возвращать ошибку, которую ты проверяешь у кода

Тест «пустое название»: в фейк положили `ErrBlankName` как ошибку `Get`. Тест зелёный, но ошибку отдал фейк, а не `SetName` — домен не работал. Если ошибка должна родиться в коде (домен), фейк должен отвечать «всё хорошо» (`err: nil`), а плохими — сделать входные данные (пустое название). Проверка — «сломай нарочно»: убери из сценария обработку ошибки `SetName`; правильный тест упадёт, этот — нет.
