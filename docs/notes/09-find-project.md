## Ошибка в `return` — сверь с тем, что функция обещала

Компилятор показывает на строку с `return`, но ошибка часто строкой выше — в объявлении результата. Сообщение `cannot use X (value of type А) as Б value in return statement` читается так: «отдаёшь А, а обещал Б».

```go
func NewPacker(keeper ParcelKeeper) *ParcelKeeper { // обещал: указатель на интерфейс
	return &Packer{keeper: keeper}                   // отдаёт: *Packer
}
```

Конструктор обещает то, что создаёт, — `*Packer`. Тип поля и параметра (интерфейс) и тип результата (сам сценарий) — разные вещи, их легко перепутать при копировании.

Хвост сообщения `pointer to interface, not interface` — подсказка: звёздочку перед именем интерфейса не пишут.

Мнемоника: **звёздочка — у кандидата, не у вакансии.** `*fridge.Fridge` — конкретный холодильник, у него есть адрес. `MilkGiver` — описание умения, адреса у описания нет. Кандидат со своей звёздочкой целиком помещается в поле типа `MilkGiver`.

```go
func NewServeLatte(milk MilkGiver) *ServeLatte  // верно
func NewServeLatte(milk *MilkGiver) *ServeLatte // ошибка: pointer to interface
```

## Как держать интерфейсы в голове: вакансия, кандидат, отдел кадров

Сказал: «не могу сложить в голове, что куда передавать; из-за этого в прошлый раз бросил Go». Модель:

- **Интерфейс — вакансия.** Пишет тот, кто нанимает (сценарий): «требуется: умеет `Find`». Только нужные на работе умения.
- **Структура — кандидат.** Живёт своей жизнью, вакансий не читает, нигде не пишет «я подхожу».
- **Конструктор сценария — собеседование.** В момент передачи компилятор сверяет умения кандидата с вакансией.
- **`main` или тест — отдел кадров.** Нанимает кандидата и приводит к работодателю. Работодатель сам никого не нанимает.

Имена:

- интерфейс — по умению: `BookFinder`, `ParcelSaver` (как `io.Reader`);
- поле — по роли: `finder BookFinder`, чтобы читалось `s.finder.Find(code)`;
- сценарий — по действию: `LendBook`;
- кандидат — по тому, что он такое: `memory.Shelf`.

Сборка всегда в три строки:

```go
shelf := memory.NewShelf()  // нанять
lend := NewLendBook(shelf)  // отдать работодателю — собеседование
lend.Call("b-42")           // работать
```

Тренажёр — `docs/drills/01-interfaces.md`.

## Имена: окончание `-er` — только у интерфейса

В Go интерфейс из одного метода называют по методу с окончанием `-er`: метод `Read` → `Reader`, `Put` → `Putter`, `Find` → `Finder`. Слово `Interface` в имя не пишут — это и так видно из объявления.

Если имя на `-er` досталось сценарию, роли путаются: читается как «умение», а на деле это «работодатель». Сценарий называют действием: `LendBook`, `ServeLatte`.

Ещё два правила:

- конструктор — `New` + имя типа: `NewLendBook`;
- получатель — одна-две буквы, одинаково во всех методах типа: `func (uc *LendBook) Call(...)`.

```go
type BookGetter interface {           // вакансия: умеет Get
	Get(code string) (*Book, error)
}

type LendBook struct {                // работодатель: что делает
	books BookGetter                  // поле: откуда брать книги
}

func NewLendBook(books BookGetter) *LendBook { ... }

func (uc *LendBook) Call(code string) (*Book, error) {
	book, err := uc.books.Get(code)   // «книги, дай»
	...
}
```

## Не знаю, с чего начать — начни с теста

Порядок «структура → методы → конструктор» не нужно помнить. Пишешь сначала, **как хочешь пользоваться** — три строки в тесте. Он не собирается, и компилятор называет первое, чего не хватает. Дописываешь только это и запускаешь снова. В голове всегда одна ошибка, а не вся схема.

```go
shelf := memory.NewShelf()   // undefined: memory.NewShelf → пишу полку
lend := NewLendBook(shelf)   // undefined: NewLendBook   → пишу сценарий
book, err := lend.Call("b-42")
```

Интерфейс при этом — **не то, что передают**, а **тип параметра**: надпись над дыркой «сюда подходит всё, что умеет `Get`». Передают конкретную полку.

В Rails так пишут через TDD: сначала `expect(LendBook.new(shelf).call("b-42"))`, потом класс.

## Поменял тип параметра — поменяй и тип поля

Конструктор кладёт параметр в поле, значит, у них должен быть один тип. Если параметр уже интерфейс, а поле ещё конкретный тип, компилятор откажет в строке `return &T{...}`: «что-нибудь, что умеет `Get`» нельзя положить в коробку под конкретное хранилище — под вакансию может прийти и не оно.

```go
type LendBook struct {
	books *memory.Shelf             // поле — конкретная полка
}

func NewLendBook(books BookGetter) *LendBook {
	return &LendBook{books: books}  // ошибка: BookGetter не *memory.Shelf
}
```

Случалось дважды: в тренажёре (`latte.go`) и в `get_project.go`. При переходе на интерфейс менять **три** места: поле, параметр, импорт (последний уйдёт сам).

## Зелёная сборка — ещё не готовая задача (ревью 1)

Ошибку «тип поля не совпадает с типом параметра» можно убрать двумя способами: поднять поле до интерфейса или опустить параметр обратно до конкретного хранилища. Компилятору всё равно, оба варианта собираются. Но второй отменяет смысл задачи: сценарий снова знает о `memory`. Проверка — `go list -f '{{.Imports}}' ./internal/usecase`: если там есть `memory`, интерфейса нет.

## Почему лишний метод в интерфейсе — плохо, хотя всё собирается (В2)

Сейчас собирается, потому что `memory.Repo` случайно умеет и `Add`, и `Get`. Вред проявится на следующем кандидате: хранилище, которое умеет только сохранять (например, запись в журнал), не пройдёт собеседование у сценария «создать», хотя тот `Get` ни разу не вызывает. Придётся дописывать метод, которым никто не пользуется. Вакансия требует больше, чем нужно на работе.

## Как назвать переменную со сценарием

Короче, чем тип, и без суффиксов `UC`, `Service`, `Instance`: тип и так виден справа в конструкторе. Обычно — глагол-действие. Чем меньше область видимости (тест, функция), тем короче имя.

```go
shelf := memory.NewShelf()
pack := NewPackParcel(shelf)
find := NewFindParcel(shelf)
parcel, err := find.Call("p-1")
```

Вызов читается как фраза: `find.Call`. Не `findParcelUC`.

## Импорты у каждого файла свои

То, что файл теста импортирует пакет, не помогает соседнему файлу того же пакета. Каждый файл перечисляет в `import` всё, чем пользуется сам, — иначе `undefined: имяПакета`.

В Ruby один `require` действует на всю программу; в Go — только на свой файл.
