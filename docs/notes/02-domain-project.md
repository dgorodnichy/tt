# Конспект к задаче 02. Доменная сущность «проект»

Пополняется по ходу задачи: сюда записывается всё, что ты спросил и что мы выяснили.

## Как запустить тесты: `go test` принимает каталог

`go test` запускает тесты **пакета**, а пакет в Go — это каталог. Не файл. Поэтому в команде указывается путь до каталога, и он должен начинаться с `./`.

```
go test ./internal/store        # тесты одного каталога
go test ./...                   # тесты всех каталогов проекта
go test ./internal/store -v     # то же, с именами тестов
```

Без `./` Go считает, что это имя пакета из стандартной библиотеки (как `net/http`), и ищет его в своей установке. Отсюда ошибка `package ... is not in std`.

Имя файла (`widget.go`) в путь не входит: все файлы каталога — один пакет, тесты запускаются для всех сразу. В RSpec ты указываешь файл (`rspec spec/models/widget_spec.rb`), в Go — каталог.

## `len` считает байты, а не буквы

`len("привет")` вернёт 12, а не 6: русская буква занимает два байта, латинская — один. Чтобы посчитать именно символы, строку считают в рунах (руна — один символ).

```go
len("box")                       // 3
len("куб")                       // 6
utf8.RuneCountInString("куб")    // 3
```

В Ruby `"куб".length` сразу даёт 3, а байты — это `bytesize`. В Go наоборот: `len` — это `bytesize`.

## Границу проверяют ровно на границе

Если правило «не больше 10», то тестов нужно два: ровно 10 (можно) и 11 (нельзя). Тест на 9 ничего не говорит о границе: он пройдёт и при `> 10`, и при `>= 10`. Ошибка на единицу (`>` вместо `>=`) — самая частая, и ловит её только тест со значением на самой границе.

## Зачем `errors.Is`, а не сравнение текста

Текст ошибки — для человека, который читает лог. Переменная-ошибка — для кода, который решает, что делать. Текст можно свободно менять (исправить опечатку, перевести), и ничего не сломается, пока код сравнивает с переменной.

```go
if errors.Is(err, ErrNegativeWeight) { ... }       // надёжно
if err.Error() == "weight must not be negative" {} // сломается от правки текста
```

В Ruby это разница между `rescue NegativeWeightError` и `rescue => e; if e.message == "..."`.

## Большая и маленькая буква: граница — пакет

Имя с большой буквы видно из любого пакета. Имя с маленькой — только внутри своего пакета, то есть из всех файлов этого каталога. Не «только из конструктора»: тест лежит в том же пакете и поэтому тоже читает и пишет такие поля.

```go
type Parcel struct {
	weight int // видно только внутри пакета
}
```

Из другого пакета написать `Parcel{weight: -1}` или `p.weight = -1` нельзя — не скомпилируется. Остаётся один путь — конструктор. Так и держится обещание «объект всегда корректен».

В Ruby похоже на `private`, только граница — не класс, а весь каталог.

## Кто следит, что домен не зависит от HTTP

Никто. Компилятор разрешит импортировать `net/http` куда угодно. Он ругается только на импорт, который не используется (`imported and not used`), — это другая ошибка, не про архитектуру.

Правило «домен ничего не знает про HTTP и базу» держится на нас самих: на ревью и на проверке командой.

```
go list -f '{{.Imports}}' ./internal/store
```

Позже это можно поручить линтеру.

## Первичный и внешний ключ

`id` самой записи — первичный ключ (primary key). Внешний ключ (foreign key) — это поле, которое хранит чужой `id`: у посылки `store_id` указывает на склад.

## Имя пакета — по имени каталога

В первой строке файла (`package ...`) принято писать имя каталога, в котором файл лежит. Файл `internal/store/widget.go` начинается с `package store`, а не `package widget`.

Компилятор это не проверяет, но снаружи пакет подключают по пути каталога, а обращаются по имени из `package`. Если они разные, читатель путается: импортировал `.../store`, а писать надо `widget.Что-то`.
