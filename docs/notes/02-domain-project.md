# Конспект к задаче 02. Доменная сущность «проект»

Пополняется по ходу задачи: сюда записывается всё, что ты спросил и что мы выяснили.

## Как запустить тесты: `go test` принимает каталог

`go test` запускает тесты **пакета**, а пакет в Go — это каталог. Не файл. Поэтому в команде указывается путь до каталога, и он должен начинаться с `./`.

```
go test ./internal/store        # тесты одного каталога
go test ./...                   # тесты всех каталогов проекта
go test ./internal/store -v     # то же, с именами тестов
```

Без `./` Go считает, что это имя пакета из стандартной библиотеки (как `net/http`), и ищет его в своей установке. Отсюда ошибка `package ... is not in std`.

Имя файла (`widget.go`) в путь не входит: все файлы каталога — один пакет, тесты запускаются для всех сразу. В RSpec ты указываешь файл (`rspec spec/models/widget_spec.rb`), в Go — каталог.

## Имя пакета — по имени каталога

В первой строке файла (`package ...`) принято писать имя каталога, в котором файл лежит. Файл `internal/store/widget.go` начинается с `package store`, а не `package widget`.

Компилятор это не проверяет, но снаружи пакет подключают по пути каталога, а обращаются по имени из `package`. Если они разные, читатель путается: импортировал `.../store`, а писать надо `widget.Что-то`.
