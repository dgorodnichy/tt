# Конспект к задаче 11. Сценарий «список проектов»

Пополняется по ходу задачи: сюда записывается всё, что ты спросил и что мы выяснили.

## Почему печатаются адреса `0x…`, а не проекты

`%v` для указателя печатает адрес — «проект лежит вот здесь». В `map[string]*Widget` значения — указатели, поэтому видно `map[1:0x268f…]`. Чтобы увидеть содержимое: пройти циклом и вызвать свои методы (`w.Name()`), или напечатать то, что по адресу, — `*w` с `%+v` (поля с именами).

```go
for id, w := range widgets {
	t.Logf("%s: %q", id, w.Name())
}
t.Logf("%+v", *widgets["1"])
```

## В тестах печатать через `t.Logf`

`fmt.Printf` в тесте печатает без файла и строки, и без `\n` склеивается с `--- PASS`. `t.Logf` пишет в отчёт теста с местом вызова и сам ставит перевод строки; видно с `go test -v`. В RSpec так же: `puts` в спеке работает, но мешается с выводом раннера.

## Почему хранилище не отдаёт свою `map` наружу

`map` при передаче не копируется: получатель держит ту же самую `map`, что внутри хранилища, и может добавить или удалить запись мимо `Add`. В Ruby — как отдать `@items` вместо `@items.values`. Вторая причина: будущая база отдаёт строки, а не `map`; срез «вот все проекты» может вернуть любое хранилище.

## Как собрать срез из `map` — четыре шага

1. Пустой срез.
2. `range` по `map` — нужен только элемент, ключ в `_`.
3. `срез = append(срез, элемент)`.
4. Вернуть срез.

## `is not an expression` — написал тип там, где нужно значение

`return []*Widget` — ошибка: это тип, как `return Array` в Ruby. Значение пустого среза: `var ws []*Widget` (переменная) или `[]*Widget{}` (литерал с фигурными скобками). Для сборки через `append` — завести переменную в начале и вернуть её в конце.

## `append` — функция, а не метод среза

`ws.append(ws, w)` — привычка из Ruby (`array.push`). У среза в Go методов нет; `append`, как и `len`, — встроенная функция: срез передают первым аргументом, а результат присваивают обратно — `ws = append(ws, w)`.

## Куда ставить интерфейс — вывести, а не вспомнить

После перерыва забыл, «куда потом передать интерфейс». Рассуждение:

1. Сценарий вызывает метод через своё поле: `uc.widgets.All()`.
2. Что можно вызвать у поля — решает его тип. Если тип `*memory.Shelf`, сценарий знает о `memory`.
3. Сценарию нужно одно — метод `All()`. Тип «что угодно с `All()`» — это интерфейс. Значит, он — тип поля.
4. Конструктор кладёт параметр в поле — тип параметра тот же.
5. Тест передаёт `memory.NewShelf()` — подходит, потому что у него есть `All()`.

**Интерфейс — это просто тип. Он стоит там, где раньше стоял конкретный тип хранилища: в поле и в параметре.** Больше нигде.

В Ruby `def initialize(widgets)` тип не пишет — подойдёт всё, что умеет `.all`. Go требует тип; интерфейс и есть «всё, что умеет `All()`».

Проверка: `go list -f '{{.Imports}}' ./internal/usecase` — `memory` пропал.

## Когда нужен интерфейс — три вопроса

Сказал: «отложилось только "заменяем memory на интерфейс", но в другой ситуации я не пойму, от чего избавляться». Способ, который работает в любом коде:

1. **Что мой код вызывает у чужого объекта?** — выписать методы.
2. **Захочу ли я подставить сюда другое?** (базу вместо памяти, фейк в тесте). Нет — конкретный тип, интерфейс не нужен. Да — к п. 3.
3. **Интерфейс = методы из п. 1**, объявлен рядом с моим кодом, стоит типом поля и параметра.

Короткая форма п. 2: «захочу ли я подменить это в тесте?». В RSpec подменяют хранилище, почту, HTTP-клиент, время — именно их в Go прячут за интерфейсом.

Обратный пример: сценарий пользуется `domain.Project` напрямую, без интерфейса — проект никто не подменяет. Интерфейс не везде, а только там, где на месте объекта может оказаться разное.

## Не получается с пустого листа — это нормально

Попробовал переписать сценарий по памяти — не смог. Восстановить файл с нуля через пару дней — самая трудная форма проверки; в Rails новый контроллер тоже пишут, глядя на соседний. Рабочий способ — тест уже описывает пользование, дальше по одной ошибке компилятора. Форма сценария — четыре блока: интерфейс (что вызываю) → структура с полем этого типа → конструктор, кладёт параметр в поле → `Call`, вызывает метод поля. Образец — соседний сценарий (`get_project.go`), открыть рядом — нормально.

## Есть ли значение в срезе — `slices.Contains`

`slices.Contains(fruits, "pear")` — как `include?` в Ruby (пакет `slices`, Go 1.21+). Если в срезе указатели на объекты, сначала собрать нужное поле в срез строк (`range` + `append` с `w.Name()`), потом проверять `Contains` для каждого ожидаемого. Порядок при этом не важен.
