# Задача 10. Своё хранилище в тестах

Этап 2. Задача маленькая. Новой темы Go нет. Одна новая мысль: **интерфейс сценария можно реализовать своим типом прямо в тесте.** Такой тип называют фейком (fake) — это мок, написанный руками.

## Зачем

Сейчас тесты сценариев проверяют только то, что умеет `memory.Repo`. Две вещи так не проверить:

- **Сценарий «создать» не сохраняет, если домен отказал.** Сейчас это видно только косвенно: в `memory` проекта нет. Хочется спросить напрямую, звали ли `Add` вообще.
- **Сценарий «найти» возвращает любую ошибку хранилища как есть,** а не только «не найдено». `memory` других ошибок не выдаёт, а у будущего SQLite будут, например «база недоступна».

Для обеих проверок нужно хранилище, которое ведёт себя так, как нужно тесту.

## На что это похоже

| | Сейчас в тестах | В этой задаче |
|---|---|---|
| интерфейс | `Adder`, `Getter` | те же, **не меняются** |
| что передаём в конструктор | `memory.NewRepo()` | свой тип из файла `_test.go`: считает вызовы или всегда отказывает |
| сценарий | `CreateProject`, `GetProject` | те же, **не меняются ни на символ** |

В Rails так делают через `double` и `allow(...).to receive`. В Go библиотека не нужна: фейк — обычный тип с тем же методом, что в интерфейсе.

## Что сделать

1. В файле теста сценария «создать» — свой тип с методом `Add`, который **запоминает, сколько раз его позвали**.
2. Тест: пустое название → ошибка домена **и** `Add` не вызывался ни разу.
3. Тест: всё верно → `Add` вызван ровно один раз.
4. В файле теста сценария «найти» — свой тип с методом `Get`, который **всегда возвращает заданную ошибку**. Ошибку объяви в тесте сам (например, «storage is down»).
5. Тест: сценарий «найти» вернул именно эту ошибку (через `errors.Is`) и не вернул проект.

Двигайся как в тренажёре: сначала три строки сборки в тесте, потом по одной ошибке компилятора.

## Критерии приёмки

- `go test ./...` проходит. Старые тесты на месте и зелёные.
- Три новых теста из списка выше.
- Фейки объявлены в файлах `_test.go`. Причина: они нужны только тестам и не попадают в программу.
- Файлы сценариев `create_project.go` и `get_project.go` не изменены: `git diff 38a5869 -- internal/usecase/create_project.go internal/usecase/get_project.go` пуст. Это и есть смысл интерфейса: сценарию всё равно, какой тип ему передали, лишь бы у него был нужный метод.
- Пакеты `memory`, `domain` и `cmd/api/main.go` не изменены.
- `go vet ./...` чист, `gofmt -l .` пуст, `git status` чистый, опыты убраны (`git diff` пуст перед сдачей).

## Приём на абстрактном примере

Упаковщику нужен `ParcelKeeper` с методом `Put`. Фейк-счётчик в тесте:

```go
type countingKeeper struct {
	puts int
}

func (k *countingKeeper) Put(p *Parcel) {
	k.puts++
}
```

```go
keeper := &countingKeeper{}
packer := NewPacker(keeper)
packer.Call("") // плохой код посылки

if keeper.puts != 0 {
	t.Errorf("Put called %d times, want 0", keeper.puts)
}
```

Звёздочка у получателя здесь обязательна: без неё `k.puts++` увеличит копию, и тест всегда увидит `0`.

Фейк, который всегда отказывает, — тип с одним полем-ошибкой; его метод возвращает `nil` и это поле.
