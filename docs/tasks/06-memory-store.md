# Задача 06. Хранилище проектов в памяти

Начало этапа 2. Одна новая тема Go: **`map`** — то, что в Ruby называется `Hash`.

## Зачем

Проект теперь можно создать, и у него есть идентификатор. Но созданный проект живёт, пока жива переменная: положить его куда-то и потом достать по идентификатору нельзя.

До базы данных ещё далеко. Начнём с самого простого хранилища: проекты лежат в памяти программы, в `map`, ключ — идентификатор. Этого хватит, чтобы дальше строить всё остальное, а базу подставить позже.

## Маленький хвост с задачи 05

Исправлено: `internal/domain/project_test.go:42` и `:46` теперь `Errorf`. Осталось закоммитить эту правку отдельным коммитом до начала работы над хранилищем.

## Что сделать

1. Новый каталог `internal/adapter/memory`, пакет `memory`. Это первый пакет проекта, который пользуется доменом снаружи.
2. В нём тип-хранилище. Внутри — `map`, где ключ — идентификатор проекта, а значение — проект.
3. Конструктор хранилища.
4. Метод «сохранить»: принимает проект и кладёт его в `map` под его идентификатором. Если проект с таким идентификатором уже лежит — заменяет.
5. Метод «найти»: принимает идентификатор, возвращает проект и ошибку. Если такого нет — ошибка-переменная «не найдено», объявленная в этом же пакете.
6. Тесты в этом же каталоге.

Двигайся по шагам: тип и конструктор → «сохранить» и «найти» для одного проекта → тест → случай «не найдено» → тест → замена → тест.

## На что это похоже

Форма та же, что ты уже делал в задачах 02–03 с проектом: **тип с закрытым полем → конструктор → методы**. Новое здесь одно: поле — не строка, а `map`.

| | Проект (02–03) | Хранилище (06) |
|---|---|---|
| закрытое поле | строка с названием | `map` с проектами |
| конструктор | проверяет название, заполняет поля | создаёт пустой `map`, кладёт в поле |
| методы | прочитать название, сменить название | найти, сохранить |

`map` создаётся внутри конструктора. Снаружи его никто не передаёт и не видит.

Файл в каталоге `internal/adapter/memory` назови по тому, что в нём лежит, маленькими буквами. Go имя файла не проверяет; тесты — в файле с тем же именем и `_test.go` на конце.

Если непонятно, с чего начать, сделай только первый шаг и остановись: тип, конструктор и один тест, который создаёт хранилище и проверяет, что оно не `nil`. Это уже можно показать.

## Критерии приёмки

Каждый критерий можно проверить командой или глазами.

- `go test ./...` проходит, в выводе два пакета с тестами: `internal/domain` и `internal/adapter/memory`.
- Тесты хранилища покрывают четыре случая:
  - сохранил проект, нашёл по идентификатору — название и описание те же;
  - ищу идентификатор, которого нет, — ошибка «не найдено» (через `errors.Is`), проекта нет;
  - сохранил два разных проекта — каждый находится по своему идентификатору;
  - сохранил второй проект с тем же идентификатором — находится второй.
- Поле с `map` начинается с маленькой буквы. Проверка: из теста домена или из `main.go` написать `store.имяПоля` не получится — так же, как было с `p.name`.
- `go list -f '{{.Imports}}' ./internal/domain` — как раньше, только стандартная библиотека. Домен про хранилище не знает (почему — вопрос 3).
- `go list -f '{{.Imports}}' ./internal/adapter/memory` показывает стандартную библиотеку и домен, больше ничего.
- В пакете `memory` два метода: сохранить и найти. Удаления, списка, поиска по названию нет: о них никто не просил, а каждый метод с большой буквы — обещание, которое потом придётся держать (вспомни `SetID`).
- В пакете нет слова `interface`. Интерфейс появится, когда у хранилища появится тот, кто им пользуется.
- `cmd/api/main.go` не изменён: `/healthz` отвечает `{"status":"ok"}`.
- `go vet ./...` чист, `gofmt -l .` пуст, `git status` чистый.

## Приём на абстрактном примере

Сам `map`:

```go
stock := make(map[string]int) // ключ — строка, значение — число

stock["apple"] = 3            // записать
n := stock["apple"]           // прочитать: 3

n, ok := stock["pear"]        // ключа нет: n == 0, ok == false
if !ok {
	// такого ключа нет
}
```

`map` внутри своего типа:

```go
type Shelf struct {
	items map[string]int
}

func NewShelf() *Shelf {
	return &Shelf{items: make(map[string]int)}
}
```

## Мостики из Ruby

- `make(map[string]int)` — это `{}`. Отличие: типы ключа и значения объявляются заранее и не меняются.
- `stock["pear"]` для отсутствующего ключа в Ruby даёт `nil`. В Go — «пустое» значение нужного типа: `0` для числа, `""` для строки. Отличить «ключа нет» от «лежит ноль» можно только вторым значением `ok`.
- `n, ok := stock[key]` — это `stock.key?(key)` и `stock[key]` за один раз.
- `stock.fetch("pear")` в Ruby бросает `KeyError`. Твой метод «найти» делает то же, но по-Go: возвращает ошибку-значение.

4. В Ruby `{}["нет"]` даёт `nil`. Что вернёт твой `map` для идентификатора, которого нет, если читать без `ok`? Проверь через `fmt.Println` в тесте, приведи вывод, потом убери.
