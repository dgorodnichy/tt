# Задача 11. Сценарий «список проектов»

Этап 2. Задача маленькая. Новое в Go: **собрать срез из `map`** — цикл `for ... range` по `map` и `append`. Одна новая мысль: **у `map` нет порядка.**

## Зачем

Проект можно создать и найти по идентификатору, а увидеть все разом нельзя. Добавим третий сценарий: «список проектов».

## На что это похоже

Форма та же, что у сценариев 07–09: интерфейс в один метод → тип с полем этого интерфейса → конструктор → один метод.

| | Найти проект (09) | Список проектов (11) |
|---|---|---|
| метод хранилища | `Get(id)` — один проект или ошибка | новый: все проекты срезом |
| интерфейс | свой, один метод | свой, один метод |
| сценарий | принимает id, возвращает проект и ошибку | ничего не принимает, возвращает срез |

Новое — только внутри хранилища: пройти по `map` и сложить значения в срез. Срезы и `range` по срезу ты уже видел в табличных тестах (задача 04).

## Что сделать

1. В `memory` — новый метод: возвращает все проекты срезом `[]*domain.Project`. Ошибки не возвращает — хранилищу в памяти нечему ломаться (как у `Add`).
2. Тесты `memory`: пустое хранилище → срез длины 0; положили два проекта → длина 2, и оба идентификатора в нём есть.
3. В `usecase`, в новом файле, — свой интерфейс с одним методом, сценарий, конструктор, один метод.
4. Тест сценария на настоящем хранилище: создал два проекта сценарием «создать», получил список сценарием «список» — в нём оба, с правильными названиями.

## Приём на абстрактном примере

`range` по `map` даёт ключ и значение:

```go
prices := map[string]int{"apple": 3, "pear": 5}

for name, price := range prices {
	fmt.Println(name, price)
}
```

`append` добавляет в срез и **возвращает новый срез** — результат нужно присвоить:

```go
var names []string
names = append(names, "apple")
names = append(names, "pear")
// len(names) == 2
```

## Ловушка: у `map` нет порядка

Go нарочно перемешивает порядок обхода `map` при каждом запуске. Если положил «apple», потом «pear», цикл может выдать сначала «pear». Поэтому тест вида «первый элемент — apple» иногда проходит, иногда падает.

Как проверять без порядка: длину — через `len`, а наличие каждого — по идентификатору (например, разложить результат обратно по id или пройти циклом и отметить найденные).

## Мостики из Ruby

- `hash.values` в Ruby — здесь пишешь сам: `range` + `append`.
- В Ruby `Hash` помнит порядок вставки. В Go `map` — нет. Это главное отличие, на котором и ловятся.
- `array << x` меняет массив на месте. `append` в Go так не делает: без `s = append(s, x)` результат потеряется.
