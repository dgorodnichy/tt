# Задача 12. Сценарий «удалить проект»

Этап 2. Задача маленькая. Новое в Go — одна встроенная функция: **`delete` для `map`**. Новой мысли про устройство кода нет: это четвёртый сценарий той же формы.

## Зачем

Проект можно создать, найти и получить списком, а удалить нельзя.

## На что это похоже

| | Найти проект (09) | Удалить проект (12) |
|---|---|---|
| метод хранилища | `Get(id)` — проект или «не найдено» | новый: удалить по id, ошибка «не найдено», если нет |
| интерфейс | свой, один метод | свой, один метод |
| сценарий | принимает id, возвращает проект и ошибку | принимает id, возвращает только ошибку |
| ошибка хранилища | возвращается как есть | возвращается как есть |

Форма сценария — те же четыре блока: интерфейс → структура с полем этого типа → конструктор → `Call`. Образец — `get_project.go`, открывай рядом.

## Что сделать

1. В `memory` — метод удаления по идентификатору. Возвращает ошибку: `ErrProjectNotFound`, если такого нет; `nil`, если удалил.
2. Тесты `memory`:
   - удалил существующий → `Get` по этому id даёт «не найдено»;
   - удаление несуществующего → `ErrProjectNotFound`;
   - было два, удалил один → второй на месте.
3. В `usecase`, в новом файле, — свой интерфейс с одним методом, сценарий, конструктор, `Call`. Ошибку хранилища возвращает как есть.
4. Тесты сценария:
   - на настоящем хранилище: создал сценарием «создать», удалил сценарием «удалить», сценарий «найти» говорит «не найдено»;
   - с фейком (как в задаче 10): хранилище вернуло свою ошибку — сценарий вернул именно её.

## Что изучить

- `go doc builtin.delete` — короткая, нужна для вопроса 3.

## Приём на абстрактном примере

```go
prices := map[string]int{"apple": 3, "pear": 5}

delete(prices, "apple")
// len(prices) == 1, "apple" больше нет
```

`delete`, как `append` и `len`, — встроенная функция, а не метод `map`. В Ruby — `hash.delete("apple")`.

## Мостики из Ruby

- `hash.delete(key)` в Ruby возвращает удалённое значение или `nil`. `delete` в Go не возвращает ничего — узнать, был ли ключ, нужно самому, заранее. Как — ты уже делал в `Get`.
- `destroy!` в Rails бросает исключение, если записи нет. Здесь — ошибка-значение `ErrProjectNotFound`.
